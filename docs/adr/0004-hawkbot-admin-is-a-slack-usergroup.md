# HawkBot Admin authorization moves from Slack Owner/Admin to a dedicated Slack User Group

Every admin-gated Hawk Bot capability (`/hawk config`, `/hawk event create`, the season CSV export, the Reaction Cutoff Verification failure DM) now checks membership in a dedicated Slack User Group — configured by an admin via its handle, resolved once to the group's id — instead of Slack's own workspace Owner/Admin flag. This is a full replacement, not an additional check alongside the old one.

Workspace Owner/Admin was the simplest possible answer with zero setup, which is why it was the original choice (see `CLAUDE.md`'s "authorization comes from Slack" reasoning). But it's also too broad: it ties Hawk Bot's admin duties to full Slack workspace administration — billing, every app's permissions, every channel — when what a team actually needs is a smaller set of people (mentors, team leads) trusted with this one bot's admin commands. A dedicated User Group scopes that down while staying genuinely Slack-native: it's not a list this app invents and has to keep current, it's a Slack feature managed the same way channels or other user groups are.

**Bootstrap safety net**: Slack workspace Owners always retain HawkBot Admin rights regardless of the group's configuration state. Without this, an empty or never-configured group would mean nobody could run the one command (`/hawk config set`) needed to fix it — a real lockout, not a theoretical one. Owner status costs nothing to check and is already the highest-trust role in the workspace, so it's a reasonable permanent fallback rather than a gap to close later.
