# FTC meetings stay on the Team Meeting Calendar and check in to an opt-in channel

The team's students mentor several FTC teams as a focus area, like scouting or manufacturing. There is one team and one roster of students: any student can show up to an FTC meeting and should earn hours for it. Mentors who open the shop need one calendar that lists every time anyone is in the building, so FTC meetings live on the Team Meeting Calendar. The cost, until now, was that each one got an Event Check-in Post in the announcements channel, where students not involved with FTC checked in to the wrong event and the channel filled with posts that weren't actionable for "all" of the team (issue #61).

An **FTC Event** is a Team Meeting Calendar Event whose title **starts with** a marker an admin sets (`ftc_event_marker`; the team's convention is 🟧), ignoring leading whitespace and case. It must lead the title, not merely appear in it: joint meetings are titled like "Team Meeting 🟦 🟧 (FRC and FTC 26623 BtheBs)", carrying 🟧 as a tag, and those are for everyone and belong in the announcements channel. "🟧 FTC Team Meeting (36584 RAS)" is an FTC Event. It differs from every other Team Meeting Event in exactly one way: **its Check-in Post goes to `ftc_channel`, a public opt-in channel (#pipeline-ftc), instead of `announce_channel`.** The title names which FTC team is meeting, so students supporting a particular team can tell. Nothing else forks:

- **Same team, same hours.** Attendance, the Reaction Cutoff, timing, the Event Attendance Report (same report channel) and the Season totals and CSV all run as for any Team Meeting. Hours and attendance % are combined; nothing is split by FRC/FTC.
- **The Roster is still the membership of the channel the post went to, at the moment it posted** (`postCheckinPost` snapshots whatever channel it is given). For an FTC Event that is the students who opted in to the FTC channel: they are expected to answer, and everyone else is neither asked nor charged a No Response.
- **Anyone who ends up Attending joins the Roster at the Reaction Cutoff, for every Event, not only FTC ones.** Season totals, the CSV and the per-Event report all join through the Roster, so today a student who joined the channel after the post went out, reacted 👍 and came to the meeting is recorded as attending but silently never shows up in any of them. The cutoff already loops over Attending rows to credit hours; it adds them to the Roster in the same loop (`snapshotRoster` already ignores duplicates), before the post is locked and the report is built. Only 👍 adds a person: a ❌, a clock-only reaction or no response from someone outside the Roster is ignored, because they never opted in to being asked.
- **The Weekly Summary Post lists FTC Events with a pointer to where to check in.** Each FTC line ends with a link to the FTC channel (for example `check in: #pipeline-ftc`), so students know where that meeting's post will be. It is also the bug check for the title convention below: a joint meeting wrongly led by 🟧 shows the pointer in front of the whole team, days before its post goes out, rather than only to an admin who happened to run a command. The pointer comes from the same pure function that picks the check-in channel, so it cannot disagree with the routing, and for an Event whose post is already out it shows where the post actually went. Only Events routed away from the announcements channel get one, and only while the feature is on, so nothing changes for any other line.
- **Calendar Role is untouched.** An FTC Event is `team_meeting`, synced, diffed, edited and removed like any other. Calendar Role says _which calendar_ an Event came from and is fixed at first sync; FTC-ness is a property of the title and can change with an edit.

Enabled only when **both** settings are set, the same shape as the Mentor/Teacher Summary needing its calendar and its channel. With either unset, every Event checks in to `announce_channel` exactly as before, so the feature can't half-work.

**Decided once, at post time.** The channel is chosen when the Check-in Post is sent and then lives in `events.checkin_channel`, which everything downstream already reads (reactions, resync, edits, lock, removal). Adding or removing the marker after the post is out does not move it; Calendar Change Handling reports the title edit as it would any other. Adding the marker before the post is out simply routes it.

## Alternatives considered

- **A fourth, FTC calendar as a Calendar Role.** The point of the issue is that mentors have _one_ place to look, and the team already invites the main calendar onto FTC events, so the events are already syncing. Reading a second calendar would add a cross-calendar duplicate problem, and a new `calendar_role` value means widening a `CHECK` constraint, which in SQLite is a rebuild of `events`, the table with the most foreign keys pointing at it.
- **A stored `is_ftc` column.** It goes stale when the marker setting is first set or later changed, needing a backfill for every event already synced. Deriving it from the title at post time needs no migration and has nothing to go stale.
- **Event colour, a hidden description tag, or guessing from "FTC" in the title.** Colour and description tags are invisible in the places people read titles (Slack digests, phone widgets). A text guess misfires on "FRC + FTC joint build". An emoji or bracketed tag in the title is already the team's habit, and visible everywhere.
- **Suppress FTC check-ins entirely.** Rejected by the team: FTC hours should land in the same log.
- **The whole team as the FTC Roster.** Every student would collect a No Response for every FTC meeting, including students who never saw the post, which drags down attendance % for not opting in.
- **No Roster for FTC Events; only attendees recorded.** Nobody could be a No Response, so each FTC meeting would count 1 of 1 for everyone who went, inflating attendance % the more FTC meetings someone attends.

## Consequences

- **No migration, no new scope, no manifest change.** Two settings in `domain/settings.ts`; one pure function choosing the check-in channel, used by `postDueCheckins`; the roster addition in `attemptEventCutoff`; the alert filter below; and the check-in pointer on the summary line, which the `/hawkbot calendar` preview shares.
- **The No Response Alert ignores FTC Events.** FTC is an opt-in focus area, so not answering an FTC post isn't disengagement from the team; the alert is judged on whole-team Check-in Posts only. If a streak mixed the two, students who opted in to the FTC channel would be judged on different events than everyone else under the same threshold. `getRecentOutcomesForUser` skips events whose `checkin_channel` is the configured `ftc_channel` (and filters nothing while the feature is off). It excludes the FTC channel rather than requiring `announce_channel`, so changing the announcements channel later doesn't erase everyone's history; if `ftc_channel` is changed, old FTC meetings can re-enter the window until it rolls past them. Everyone in the FTC channel is also in the announcements channel, so no one falls outside the alert's view.
- **Two conventions are kept by hand, not guarded.** A joint meeting never leads with 🟧, since one that did would post to the FTC channel only and the rest of the team would miss it. And FTC and FRC meetings are not scheduled to overlap, because a student reacting 👍 to both would be credited both. The Weekly Summary's check-in pointer (above) is the early warning for the first. `/hawkbot calendar` renders its lines through the same formatter, so it shows the same pointer, informational only, for debugging.
- **Posting must not let one bad channel block the rest.** `postDueCheckins` currently has no per-event guard; an unusable FTC channel (archived, deleted or mistyped; the bot joins a public channel itself, so a missing invite isn't the risk) would throw on its first event and stop every Check-in behind it, FRC included, on every 5-minute tick. The loop catches per event, carries on, and rethrows an aggregate at the end so the scheduler's diagnostics still show the step as failed.
- **Slack rewrites an emoji typed into a slash command.** Confirmed on the team's workspace, for both pasting and Slack's emoji picker: 🟧 typed into `/hawkbot config set` arrives as `:large_orange_square:`, which would store cleanly and never match a Google Calendar title. Validation of `ftc_event_marker` therefore rejects `:shortcode:`-shaped values, and the message says why and points at the web configuration page, which takes the real character; a plain-text marker such as `[FTC]` works through either. A small table mapping the coloured-square shortcodes back to emoji would let the slash command accept 🟧 too, but that is a table to maintain for a setting that is set once, so it is not built. After build, confirm end to end that the character Google sends matches the one stored: set the marker on the web page and check that `/hawkbot calendar` shows the check-in pointer on a 🟧 event.

Worth revisiting if FTC wants its own Season figures or Attendance Report channel (both were left combined on purpose), or if more programs than FTC want the same treatment, at which point the marker and channel become a small list of pairs rather than two settings.
