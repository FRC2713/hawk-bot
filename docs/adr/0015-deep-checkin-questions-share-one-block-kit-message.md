# Deep Check-in's follow-up questions share one Block Kit message, not a gated conversation

Deep Check-in asks two questions beyond the mood+⁉️ opener it shares with Quick Pulse. The natural-feeling design is a back-and-forth conversation — send one question, wait for an answer, send the next — but we rejected it for two reasons.

First, a technical constraint: Slack reactions attach to a whole message, not to a block within it, so two reaction-based questions can never share one message and be told apart by which was reacted to. Second, a fully gated conversation needs a small per-student state machine ("which question are they on"), which has to survive a bot restart mid-window, and silently strands anyone who answers the first question and then goes quiet — they just never receive the rest.

Instead, the two follow-up questions ride in a single message as two `radio_buttons` Block Kit elements (not plain `button`s, and not reactions) — one per question, answerable in either order, independently trackable via their own `action_id`. Plain buttons were considered and rejected: Slack's own docs are explicit that buttons have no built-in mutual exclusivity — "there's no built-in mutual-exclusivity... you'd need to implement that logic in your application layer" — so nothing stops someone tapping two answers to the same question. `radio_buttons` enforces single-selection natively (selecting a new option deselects the previous one) and persists a visible selected state via `initial_option`, which a plain button can't do. There's no state machine either way: whatever's selected by the 4-hour window's close (see CONTEXT.md, Quick Pulse Answer Window) is what's recorded, and a bot restart mid-window loses nothing, since the message and whatever's currently selected are sitting in Slack, not in the bot's memory.
