# The Informational Reply threads under the Weekly Summary Post — a narrower exception to ADR-0005, not a reversal of it

ADR-0005 rejected a threaded reply for how the Weekly Summary Post reflects changes to Team Meeting Events, specifically to avoid competing with Calendar Change Handling's own threaded notification on an Event's Check-in Post. That reasoning doesn't extend to a different calendar's digest: Informational Events never have a Check-in Post of their own to compete with. The Informational Reply is deliberately a threaded reply under the Weekly Summary Post — the one place in this app a weekly digest does thread — because threading is what keeps it visually attached to "this week" without duplicating the parent's own header and date range as a second top-level post would.

It's posted only the first time an Informational Event appears in a given week, not proactively for a week with none — an enabled Informational Calendar with nothing to report stays silent rather than adding a reply nobody needs. Once posted, it's rewritten in place for the rest of the week the same way the parent is (mirrored logic, its own item-snapshot table — `weekly_summary_informational_items`), and is deleted alongside the parent at the next weekly rollover.
